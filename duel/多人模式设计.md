# 多人模式设计（v2：1–50 人 + 角色）

> 这份文档是**重做后的目标形态**。现有的 `phira-duel`（1v1、BO3、BP 选曲）是 v1 的实现，
> 重做时会按本文档改造：协议加字段、服务端房间放宽到 50 人、客户端 UI 重画。
> 规则已经和需求方逐条确认过，不要再自行发挥。

## 1. 房间与角色

- 一个房间**最多 50 人**（配置项，默认 50）。
- 进房后选角色：
  - **打歌者**：打歌。**不能投干扰**（服务端强制，不是客户端自觉），只能"看到"干扰效果。
  - **干扰者**：不打歌，投放干扰、看谱面、聊天、给打歌者发弹幕。
- **房主**：第一个进房的人；负责选谱面。房主可以是任一角色。房主离开则顺延给下一个人。
- v1 一台服务器只有一个房间（沿用现状）。

## 2. 一局流程（一局 = 一场 = 打完就出榜）

```
进房 → 选角色 → （房主/干扰者）选一张谱面 → 所有人准备/倒计时
     → 所有打歌者同时打同一张谱面，干扰者实时投放干扰 + 发弹幕
     → 全部交卷 → 排名榜（所有打歌者按分数/准度排）
     → 一局结束（不自动开下一局，回房间状态，房主可以再选一张）
```

- **曲池**：曲池 = 房间里**所有打歌者本地谱面的交集**？不 —— 改为 **房主/干扰者从自己的本地谱面里选**，
  但必须**所有打歌者都拥有**这张谱面，否则拒绝并提示"X 没有这张谱面"。
  （协议里每个客户端上报自己的本地谱面 id 列表，服务端做校验。）
- **名次规则**：分数降序 → 同分比准度 → 再同分并列。

## 3. 干扰

- 谁能投：**只有干扰者**。打歌者投干扰由**服务端拒绝**，并回一条明确原因。
  "打歌者能不能投"是**服务端策略**，在 **PC 端开服器**里设置（默认：不能投）。
- **指定目标**：每次投放要指定一名**打歌者**（协议里带 `target`）。
  这样 50 人的场合是"针对某人"，不是"全场环境事件"。
- 能量：干扰者共享一套能量规则（Perfect/Good 那套不适用了，改为**时间回能**：
  每秒 +N，上限 100），具体数值放配置。
- 冷却：每种干扰独立冷却（沿用现状，8 秒）。
- 开局锁定：开局前 N 秒（默认 10 秒）不能投。
- 种类（沿用现有四种纯视觉干扰）：迷雾 / 抖线 / 噪点 / 压暗。

## 4. 弹幕与聊天

- **弹幕**：干扰者可以给打歌者发一条短弹幕（比如"加油"、"别慌"），
  在打歌者屏幕上飘过（位置/时长配置）。发送有频率限制（默认 2 秒一条）。
- **聊天**：房间里所有人可以聊天（沿用标准联机那种输入框 + 消息列表）。

## 5. 开服器（PC 端）要提供的设置

| 设置项 | 默认 | 说明 |
|---|---|---|
| 打歌者能否投干扰 | **关** | 需求明确要求默认不能 |
| 房间人数上限 | 50 | 1–50 |
| 干扰种类开关 | 全开 | 逐项开关（迷雾/抖线/噪点/压暗） |
| 能量回复速度 | 8/秒 | 干扰者的能量来源 |
| 冷却时间 | 8 秒 | 每种干扰独立 |
| 开局锁定 | 10 秒 | |
| 是否允许弹幕 | 开 | |
| 弹幕频率上限 | 2 秒/条 | |

这些设置**由服务端持有并下发给客户端**，客户端只显示、不自行决定。

## 6. 协议改动（相对于 v1）

新增 / 修改：

| 消息 | 方向 | 说明 |
|---|---|---|
| `Hello { room, name, charts, role }` | C→S | 加 `role` |
| `SetRole { role }` | C→S | 进房后改角色 |
| `Chat { text }` | C→S | 聊天 |
| `Danmaku { target, text }` | C→S | 给某个打歌者发弹幕 |
| `PickChart { chart }` | C→S | 房主/干扰者选谱（替代 v1 的 ban/pick） |
| `Ready { ready }` / `Start {}` | C→S | 准备；房主开局 |
| `Cast { kind, target }` | C→S | 加 `target` |
| `RoomState { settings, players: [{name, role, score, online}], phase, chart, host }` | S→C | 替代 v1 的零散状态 |
| `ChartPicked { chart, by }` | S→C | 选了哪张 |
| `RoundStart { chart, starts_in_ms }` | S→C | 沿用 |
| `PlayerProgress { player, score, accuracy, combo, energy }` | S→C | 所有打歌者的进度 |
| `Attacked { kind, from, duration_ms }` | S→C | 只发给被打的那个打歌者 |
| `Danmaku { from, text }` | S→C | 发给被打歌者（飘屏）与所有干扰者（看到别人发了什么） |
| `Chat { from, text }` | S→C | |
| `Ranking { entries: [{player, score, accuracy, max_combo, rank}] }` | S→C | 一局结束的排名榜 |

删除：`Ban` / `Pick` / `BpTurn` / `BpDone` / `NextStep`（BP 与 BO3 取消）。

## 7. 客户端 UI（这次一起美化，不要再挤在歌单顶部）

现状问题（需求方原话："按钮全部糊一起了"）：v1 把状态条画在歌单界面顶部
（`y = -ui.top`，高 0.36），那片区域本来就是歌单自己的顶栏；BP 面板紧接着往下画，
压在谱面网格上。**根因是"借"了选曲界面**。

重做后：

- **房间面板**（独立层，不占谱面网格）：
  - 顶部：房间码 / 服务器 / 房主 / 阶段
  - 中部：**50 人列表**（名字 + 角色徽标 + 打歌者实时分数 + 离线态）
  - 底部：角色切换（打歌者/干扰者）、聊天输入框、弹幕输入框（仅干扰者）、离开
- **干扰者视角**：能量条 + 四个干扰按钮 + **目标选择**（点玩家列表里的某个打歌者作为目标，
  选中的目标高亮）+ 曲池/选谱入口
- **打歌者视角（局内）**：只显示"谁对你用了什么"提示 + 飘过的弹幕；**没有干扰按钮**
- **排名榜**（局末）：整屏半透明面板，逐行显示名次/名字/分数/准度/最大连击，
  自己的那一行高亮；带"再来一局"（房主）

## 8. 实施顺序

1. **服务端 + 协议**：N 人房间、角色、策略开关、选谱、时间回能、指定目标干扰、
   弹幕/聊天、排名结算。**扩展 `duel/tests/`**：50 人进房、角色校验
   （打歌者投干扰被拒）、指定目标只打到目标、排名正确。
2. **开服器**：把第 5 节的设置项接进界面（发给服务端）+ 房间面板显示 50 人列表与阶段。
3. **客户端房间 UI + 局内 UI**（含美化）：独立层，不再压歌单。
4. **排名榜 + 弹幕飘屏**。

## 9. v1 明确不做（避免范围膨胀）

- 多局累计 / 赛季分 / BP / 投票选谱
- 反作弊（打歌者上报自己的分数，朋友之间玩的工具）
- 房间列表与多房间（一台服务器仍只有一个房间）
- 打歌者的语音/队伍配对
